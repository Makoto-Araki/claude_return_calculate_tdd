# 要件定義書 - Lint・型チェック

## 概要

現状このリポジトリにはlint(静的解析)・型チェックの仕組みが存在せず、コーディング規約違反や型の不整合を機械的に検出できない(設計の考慮漏れ)。四則演算エンドポイント・Kubernetesデプロイと同様に、コード品質を保つための最小限のlint・型チェック環境を整備する。

## 背景・課題

- `pyproject.toml`のdev依存には`pytest`/`httpx`のみが定義されており、lintや型チェック用のツールが導入されていない。
- ローカル実行用のlint・型チェックコマンドが `CLAUDE.md` にも記載されていない。
- CI(GitHub Actions等)も存在せず、プッシュ・PR時の自動チェックは行われていない。

## 受け入れ基準 (EARS記法)

1. WHEN 開発者がリポジトリ直下で `uv run` 経由のlintコマンドを実行した場合、THEN `apps/`・`tests/`配下のPythonコードに対して未使用import・未使用変数などの明らかなコーディング規約違反を検出できる SHALL。
2. WHEN 開発者がリポジトリ直下で `uv run` 経由の型チェックコマンドを実行した場合、THEN `apps/`配下のPythonコードに対して関数シグネチャや変数の型不整合を検出できる SHALL。
3. THE lint・型チェック SHALL `uv sync` で導入される開発依存として追加し、追加のインストール手順を必要としない。
4. THE lint設定 SHALL プロジェクトの対象Pythonバージョン(3.12+)に合わせる。
5. WHEN 既存の `apps/`・`tests/` 配下のコードに対してlint・型チェックを実行した場合、THEN エラーなく完了する(導入時点で既存コードの指摘事項があれば合わせて修正する) SHALL。

## スコープ外

- GitHub Actions等によるCIへの統合(将来検討)
- pre-commitフックによるコミット時自動実行(将来検討)
- コードフォーマッタの自動適用をコミットフローに組み込むこと(手動実行に留める)
